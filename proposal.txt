Levenshtein Distance
====================

This algorithm aims to solve the edit distance problem. For strings A and B, levenshtein
distance metric tells us the minimum number of edits that must be made to string A to
transform it into string B. For example, for inputs "tomato" and "potato" the algorithm
would output 2 because two edits need to be made to make the strings equivalent.

This algorithm can be used to quantify the differences between DNA sequences.
Because DNA can be represented with strings of characters, we can find how similar they are.

This algorithm can also be used in spellcheck software when searching for dictionary
matches for a given misspelled word.

Implemented with dynamic programming, the algorithm runs in worst and average
case of a * b where a and b are the lengths of the two input strings.

T(a, b) = a*b

Other algorithms that solve the edit distance problem are longest common subsequence, and 
hamming distance. Hamming distance only works for comparing strings of equivalent length, and
LCS measures based on subsequences in the strings, rather than just characters. Both algorithms
also run in a*b for worst and average case.

This algorithm would be of medium difficulty to implement and it would be
very easy to perform a demonstration. We would not need to use a dataset as we could create
our own with random number generator and a collection of characters.
To demonstrate, we could step through the algorithm using a visual matrix aid in a
slideshow.


Fibonacci heaps
====================

Fibonacci heaps aim to implement priority queues in a highly efficient manner. One common use is in Dijkstra's algorithm,
where the inputs are edges with weights, and the Fibonacci heap provides them back to the algorithm in priority order

Fibonacci heaps can help improve the runtime of Dijkstra and Prim algorithms due to its time complexity improvements over a binary heap

Fibonacci heaps are also used when frequently combining priority queues, as merging Fibonacci heaps happens in constant time

Asymptotic runtimes:
	Find Min:      Θ(1)
	Delete Min:    O(Log n)
	Insert:        Θ(1)
	Decrease-Key:  Θ(1)
	Merge:         Θ(1)

Other data structures that solve the same problem are normal priority queues and pairing heaps. Priority queues have a
much worse asymptotic time complexity, but have much lower constant overhead costs than fibonacci heaps. Pairing heaps
have a similar time complexity for everything decrease-key, which is O(log n). Pairing heaps also have the benefit of
having much less overhead though, and are generally faster for most scenarios.

A Fibonacci heap would be of medium difficulty to implement and it would also be of medium difficulty to demonstrate.
We would not need a dataset as we could randomly generate a graph for the demonstration. To demonstrate, we could step
through a couple cycles of Dijkstra's algorithm and show how the Fibonacci heap changes.


A* Search Algorithm
====================

The A* (A-star) search algorithm aims to find the shortest path between a starting node and a destination node in a graph. It uses a combination of the distance already traveled and a heuristic that estimates the remaining distance to determine which node to explore next.

This algorithm is commonly used in GPS navigation systems to find the shortest or fastest route between two locations.

A* is also used in video games for pathfinding, allowing characters to navigate around obstacles and efficiently reach a destination.

The algorithm works by assigning each node a value using the formula:

f(n) = g(n) + h(n)

Where g(n) is the cost of reaching the current node from the starting node, and h(n) is the estimated cost of reaching the destination.

The time complexity of A* depends on the heuristic and implementation. In the worst case, A* can have exponential time complexity based on the depth of the solution, although its performance is generally much better when using a good heuristic.

T(d) = O(b^d)

Where b is the branching factor and d is the depth of the solution.

Other algorithms that solve the shortest path problem are Dijkstra's algorithm and breadth-first search (BFS). Dijkstra's algorithm finds the shortest path without using a heuristic, meaning it may explore more nodes than A*. BFS finds the shortest path in an unweighted graph but does not account for different edge weights. A* can be more efficient than both algorithms when using an effective heuristic.

This algorithm would be of medium difficulty to implement and very easy to demonstrate. We would not need a dataset because we could generate our own grid containing obstacles, a starting point, and a destination.

To demonstrate, we could step through the algorithm using a visual grid in a slideshow, showing how A* evaluates neighboring nodes and selects the next node to explore based on its calculated cost. We could then highlight the shortest path once the destination is reached.
